# 🍼 수유 앱

시계와 젖병을 눌러 수유량을 기록하는 아이폰 홈 화면용 PWA입니다.
기록은 이 기기의 `localStorage`에 먼저 저장되고, **가족 방 코드**를 넣으면 엄마·아빠 폰이
Firebase Realtime Database로 **실시간(1~2초)** 공유됩니다.

- 앱 주소: **https://bswjys.github.io/baby-feeding/**
- 아이폰 사파리에서 열고 **공유 → 홈 화면에 추가** 하면 앱처럼 전체 화면으로 실행됩니다.

## 화면과 사용법

| 번호 | 요소 | 동작 |
| --- | --- | --- |
| ① | 동그란 시계 | 지금 시각을 부드럽게 보여 줍니다. **누르면 ② 시간이 현재 시각(10분 단위)으로 맞춰집니다.** |
| ② | 시간 박스 | 기록에 쓰일 시각 (오전/오후 표시) |
| ③ | 시계 옆 ▲▼ | ②의 시각을 **10분 단위**로 앞뒤 조절 |
| ④ | 기본량 박스 | 한 번 누를 때마다 **+10ml** (60 → 70 → 80 …). 옆의 `−`로 10ml 줄이기, **길게 누르면 60ml로 초기화**. 최대 300ml |
| ⑤ | 젖병 그림 | **누르면 기본량으로 바로 기록** (② 시각 사용). 우유 채움도가 기본량에 맞춰 움직입니다 |
| ⑥ | 젖병 옆 ▲▼ | **이번 수유량(⑦)만** 10ml 단위로 조절 (④ 기본량은 그대로) |
| ⑦ | 수유량 박스 | ⑥으로 맞춘 값. **누르면 이 수유량으로 바로 기록** |
| ⑧ | 기록 박스 | 날짜 · 시간 · 수유량 · 누적(그날의 누적). 행을 누르면 수정, `×`로 삭제(되돌리기 가능) |
| ⑨ | 주간 누적 | 일~토 7칸에 요일별 합계, 오늘 강조, ◀ ▶로 주 이동, 주간 총합 표시 |

- ④ 기본량 변경 시 ⑦ 수유량도 함께 따라갑니다(⑦을 ⑥으로 따로 만지기 전까지).
- 자정을 넘겨 기록할 때를 위해, ② 시각이 지금보다 1시간 이상 앞서면 **어제 기록**으로 저장됩니다.

## 👩 엄마 · 👨 아빠 기록자

- 헤더의 **`👩 엄마` / `👨 아빠`** 토글로 지금 기록하는 사람을 고릅니다. 마지막 선택은 이 기기에 기억됩니다.
- 기록에는 `by: 'mom' | 'dad'`가 함께 저장되고, **⑧ 기록 박스**의 날짜 아래에 작은 배지(`엄마` / `아빠`)로 표시됩니다.

## 👨‍👩‍👧 가족 실시간 공유

1. 두 폰 모두 앱을 엽니다.
2. 상단 **상태 뱃지**를 눌러 **가족 방 코드**(2~12자, 한글도 가능 · 예: `우리집`)를 입력하고 **연결하기**.
3. 한쪽에서 기록하면 다른 폰에 **1~2초 안에** 나타납니다(추가·수정·삭제 모두).

- **링크로초대**: 시트의 `📨 코드 보내기`로 `https://bswjys.github.io/baby-feeding/?room=우리집` 링크를 보내면,
  받은 폰은 **열기만 해도 자동 연결**됩니다.
- **기존 기록 병합**: 공유를 켜기 전에 이 기기에 있던 기록은 지워지지 않고 그대로 방에 합쳐집니다.
- **오프라인**: 비행기 모드·지하철에서도 `localStorage`에 먼저 저장되고, 다시 연결되면 자동으로 맞춰집니다.

### 상태 뱃지

| 표시 | 뜻 |
| --- | --- |
| `로컬 저장 모드` | 공유를 켜지 않음. 이 기기에만 저장 |
| `연결 중…` | 가족 방에 접속하는 중 |
| `● 실시간 연결됨 (방: …)` | 실시간 구독 중 (SSE). 서로 1~2초 안에 반영 |
| `연결됨 · 5초 갱신` | 실시간 스트림이 막힌 환경(일부 회사망 등)에서 4초마다 확인하는 대체 모드 |
| `오프라인 · 저장 중` | 인터넷 없음. 기록은 쌓이고 복귀 시 자동 동기화 |
| `연결 확인 필요` | 주소·권한 문제. 시트에서 주소를 확인 |

### 데이터 구조

```
rooms/{방코드}/records/{기록id}.json = { at, ml, by, updatedAt }
```

- 삭제는 실제로 지우지 않고 `{ deleted: true, updatedAt }` **표시(tombstone)** 로 남깁니다.
  그래야 오프라인이었던 폰이 다시 연결될 때 지운 기록이 되살아나지 않습니다.
- 병합 규칙: 같은 기기·서버에 같은 기록이 있으면 `updatedAt`이 **더 최신인 쪽**이 이깁니다.
- 연결은 **Firebase Realtime Database REST + EventSource(SSE)** 만 사용합니다.
  빌드 도구·SDK 없이 정적 파일 그대로 동작하고, 스트림이 안 되면 자동으로 polling으로 내려갑니다.

### 기본 연결 주소

`app.js`의 상수 하나로 관리합니다.

```js
const DEFAULT_FIREBASE_URL = 'https://baby-feeding-9f820-default-rtdb.asia-southeast1.firebasedatabase.app';
```

- 비워 두면 앱은 **로컬 전용**으로 동작하고, 공유 시트의 `연결 주소`에 직접 넣어 쓸 수 있습니다.

### 보안 메모

- 지금 Realtime Database 규칙은 누구나 읽고 쓸 수 있는 **테스트 모드**입니다.
  즉 **주소와 방 코드를 아는 사람은 그 방 기록을 볼 수 있습니다.** 코드는 가족끼리만 나누고,
  처음 만든 뒤 30일이 지나면 Firebase가 규칙을 잠그니 그 전에 아래처럼 `/rooms`만 열어 두는 것을 권장합니다.

```json
{ "rules": { "rooms": { "$room": { ".read": true, ".write": true } } } }
```

- 더 단단하게 하려면 Firebase Authentication(익명 로그인)을 붙여 `auth != null` 조건을 추가하면 됩니다.

## 백업 / 복원 / 초기화

- **백업**: 기록·기본량·삭제 표시를 `수유기록-YYYY-MM-DD.json` 파일로 저장
- **복원**: 백업 파일을 골라 현재 기록을 대체 (확인창에서 승인). 공유 중이면 방에도 반영됩니다.
- **초기화**: 모든 기록 삭제 + 기본량 60ml (공유 중이면 방에서도 지워집니다)

## 파일 구성

```

app.js                  기록/누적/주간 계산 · localStorage · 시계 · 백업 · 가족 공유(SSE+동기화)

sw.js                   오프라인 캐시 (HTML·JS·CSS 는 네트워크 우선, 아이콘만 캐시 우선)

icon-192.png icon-512.png icon-maskable-512.png apple-touch-icon.png
```

## 로컬에서 실행 / 검증

```bash
python3 -m http.server 8765
# http://127.0.0.1:8765 접속

# 자동 검증 (가짜 Firebase + 실제 Firebase 두 기기 동기화 49개 항목)
bash .dev/run-tests.sh

# 캐시 불일치(버튼 무반응) 회귀 검증 · 옛 버전 → 새 버전 업그레이드 경로 검증
python3 .dev/cache-mismatch-check.py   # http://127.0.0.1:8765 서버가 떠 있어야 함
python3 .dev/upgrade-check.py          # 혼자서 임시 서버(8767)를 띄움

# 라이브 사이트 + 실제 Firebase 확인 (테스트 방은 끝나고 자동 정리)
python3 .dev/live-cache-check.py     # 배포 후: 서비스워커 v4·캐시·버튼 동작
python3 .dev/live-check.py
python3 .dev/korean-room-check.py
```

서비스워커와 매니페스트는 `https` 또는 `localhost`에서만 동작합니다. 파일을 수정해 배포하면
**두 가지를 함께** 해 주세요. 하나만 하면 예전처럼 "버튼이 안 눌리는" 상태가 생깁니다.

1. `index.html`의 `?v=N` 을 올리기 (`./styles.css?v=N`, `./app.js?v=N`)
2. `sw.js`의 `CACHE`/`VERSION` 을 같은 번호로 올리기 (`baby-feeding-vN`)

지금은 `sw.js`가 **HTML·app.js·styles.css 를 네트워크 우선**(오프라인일 때만 캐시)으로 받기 때문에,
버전을 올리지 않고 코드만 고쳐도 다음 접속에서 새 파일이 적용됩니다. `?v=N` 은 그래도 같이 올려 주세요
(중간 캐시·프록시가 남아 있는 경우의 안전장치).
